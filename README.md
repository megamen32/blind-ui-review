# Blind UI Review

Сможет ли человек выполнить задачу при первом знакомстве с интерфейсом? При слепой проверке рецензент получает цель пользователя и первый экран. Автор держит ожидаемый маршрут при себе до конца проверки. Так можно заметить, где подпись обещает одно действие, а человек ожидает другое.

## Сценарий слепого теста

Ниже вымышленный пример для бумажного прототипа сервиса «Лунная полка». Экраны можно передавать текстом. Для каждого шага сохраните выбор рецензента, его ожидание и то, что показал следующий экран.

1. **Автор** открывает новый чат и передаёт только задание и первый экран из примера ниже. Названия следующих экранов, макет переходов и объяснения автора остаются за пределами чата.
2. **Рецензент** называет одно действие, видимую подсказку, на которую опирается, и ожидаемый результат. Если выбор неясен, он описывает, чего ему не хватает.
3. **Автор** показывает состояние прототипа после выбранного действия. Если для него нет экрана, отмечает, на чём остановилась проверка. Подсказывать следующий ход во время теста не нужно.
4. **Рецензент** заканчивает, когда видит подтверждение результата или больше не может продвинуться. Только после этого автор раскрывает задуманный маршрут и сравнивает его с наблюдениями.

**Задание для рецензента** — скопируйте в новый чат этот блок целиком.

> Ты впервые открыл «Лунную полку». Хочешь отложить книгу «Сад на Луне», чтобы вернуться к ней завтра. На первом экране видны название книги, кнопка «Читать» и значок пустой ленты без подписи. Что сделаешь и чего ожидаешь? Опирайся только на показанный экран. Дождись следующего экрана, прежде чем описывать результат.

**Пример записи автора после теста.** Рецензент выбрал ленту, приняв её за закладку. На следующем экране лента стала закрашенной. Рецензент заметил изменение, но не понял, где завтра искать книгу. Идея для повторной проверки — показать после нажатия сообщение «Сохранено» со ссылкой «К отложенным» и дать ту же задачу новому рецензенту.

## Установка и вызов в Codex CLI

Версия 1.0.0 включает навык для ведущего. Для полноценного прогона понадобятся модель Terra, отдельная сессия без контекста продукта и доступ к тестовому интерфейсу. По одному скриншоту можно проверить понимание экрана. Для проверки действий откройте тестовый кабинет в браузере.

```sh
codex plugin marketplace add megamen32/blind-ui-review@v1.0.0
codex plugin add blind-ui-review@blind-ui-tools
codex
```

В новой сессии Codex введите `$`, выберите навык `blind-ui-review` этого плагина и добавьте задание с первым экраном. Список навыков также открывается командой `/skills`.

[Формат плагина и marketplace](https://developers.openai.com/plugins/build/plugins) · [Вызов навыка в Codex](https://learn.chatgpt.com/docs/build-skills)
